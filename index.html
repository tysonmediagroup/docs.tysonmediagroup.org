Core Specification • Section 01

1. The tysonmediagroup.org Visual & Architectural Framework

Every web property operated by TYSON Media Group is built on a unified, zero-bloat HTML5/CSS3/Edge-JS architecture engineered for instant rendering, tactile skeuomorphic depth, and cross-domain visual harmony.

  • Universal Domain Typography Rule: Every domain name, corporate handle, and route (tysonmediagroup.org, my.tysonmediagroup.org, auth.my.tysonmediagroup.org, flame@tysonmediagroup.org) is strictly rendered in Cormorant Garamond Italic via the .brand-tmg-domain class.
  • 5-Theme Specular Engine: Every node supports real-time switching (persisted across all subdomains via shared .tysonmediagroup.org cookies and localStorage) between:
    1. Black Frutiger Aero (noir-aero — Default): Obsidian glass with a 50/50 specular horizon split and chrome borders.
    2. Noir Midnight (noir): Pure architectural monochrome flat black.
    3. Frutiger Aero Aqua (frutiger): Deep sapphire machined aqua glass.
    4. Nintendo Wii System Channels (wii): Authentic Wii channel grid with rounded typography and automatic dark-inverted brand banners.
    5. Nature Botanical (nature): Deep moss evergreen glass.
  • Property-Specific Web Icons & Banners: auth.my.tysonmediagroup.org uses TYSONAuthenticationIcon.jpg; my.tysonmediagroup.org uses myTYSONIcon.png and MyTYSONBanner.png; power.administration.tysonmediagroup.org uses TYSONPowerAdminBanner.png; and tysonmediagroup.org uses tysonmediagroup-icon.png and TYSONMediaGroupBanner.png.
Authentication • Section 02

2. Unified myTYSON Single Sign-On & Centralized Google OAuth 2.0

Authentication across all TYSON Media Group properties is centralized through auth.my.tysonmediagroup.org so that credentials and OAuth origins never need to be duplicated across satellite domains.

// Redirecting any TYSON property to Centralized SSO: https://auth.my.tysonmediagroup.org/?app=tmg&redirect=https://tysonmediagroup.org.myt5s.app/ // Returning to the requesting app with an HMAC-SHA256 signed session payload: https://tysonmediagroup.org.myt5s.app/?mytyson_sso=<base64_signed_session_token>
  • Google Identity Services (GIS) Flow: Users can sign in or register with one click via Google on auth.my.tysonmediagroup.org. The Cloudflare Edge API verifies the Google ID token directly with Google's tokeninfo endpoint.
  • New Google User Handle Picker (NEEDS_HANDLE): When a first-time Google user authenticates, the SSO portal presents the Handle Picker step so they can choose their custom 3+ character myTYSON username and configure their "Show Real Name Publicly" preference before issuing their session.
Identity Policy • Section 03

3. Strict Staff vs. Community Handle Architecture

To protect organizational authenticity, the myTYSON identity engine enforces a strict separation between verified TYSON Team staff and community/external accounts:

  • Verified TYSON Staff (team === "Y"): Receive official <slug>@tysonmediagroup.org corporate handles (including t@tysonmediagroup.org, flame@tysonmediagroup.org, a@tysonmediagroup.org, rpm@tysonmediagroup.org, tyson@tysonmediagroup.org, and contact@tysonmediagroup.org), display the verified white TYSON emblem badge, and are permitted to use 1-to-2 character executive slugs.
  • Community & Standard Members (team === "N"): Receive clean username slugs (minimum 3 characters, e.g. @j.gantt, @eythn, @jmay) with public profiles at tysonmediagroup.org/<username>. They are never assigned an @tysonmediagroup.org address.
Edge Storage • Section 04

4. Cloudflare D1 Database & Edge API Reference

All accounts, profile customizations (avatars, covers, bios, real-name visibility), and team blog dispatches are stored in our Cloudflare D1 database (mytyson-db) and served by mytyson-edge-api.js:

POST /api/auth/login — Verifies salted SHA-256 password hash & issues HMAC-SHA256 session POST /api/auth/register — Enforces >=3 char non-staff handle rule & persists to Cloudflare D1 POST /api/auth/google — Verifies Google JWT at the edge (signin | complete | link | unlink) GET /api/accounts — Returns sanitized public directory (strips passwordHashes & googleSub) POST /api/profile — Saves PFP, cover banner, bio, and showRealName to mytyson_profiles GET /api/blog — Returns chronological TYSON Team dispatches from mytyson_blog_posts POST /api/blog — Publishes a new dispatch (restricted to verified team === 'Y' staff)
Mobile UX • Section 05

5. Mobile Top Banner & Bottom Command Bar Architecture

On mobile viewports (<= 768px), the framework transforms into an ergonomic dual-bar interface:

  • Top Navbar on Mobile: Collapses secondary navigation links and action buttons so the top bar displays only the property's centered Banner Logo.
  • Bottom Mobile Command Bar (.tyson-command-bar): Fixed to the bottom of the screen with iOS safe-area padding, providing immediate thumb access to: 1. Sign In / Sign Out, 2. Public Profile, and 3. Gear Settings (Theme Drawer).

Git-Driven Cloudflare Pages Deployments

1. Cloudflare D1 Serverless SQL

Our identity ledger (mytyson_accounts), custom profile store (mytyson_profiles), and team blog (mytyson_blog_posts) run natively on Cloudflare D1 in Western North America (WNAM) with automatic Edge Cache read-through. Zero database servers to patch, zero connection-pool exhaustion, and instant global reads.

2. Cloudflare Workers & Pages Functions

Every API request across my.tysonmediagroup.org, auth.my.tysonmediagroup.org, and docs.tysonmediagroup.org executes inside Cloudflare's V8 isolate runtime. Using the WebCrypto API at the edge, we hash passwords with salted SHA-256 and sign sessions with HMAC-SHA256 in under a millisecond.

3. Atomic Git-to-Edge CI/CD

Every push to main across our GitHub repositories automatically builds and deploys globally to Cloudflare's Anycast network with instant SSL/TLS, HTTP/3 (QUIC), and atomic rollbacks across all 45+ tysonmediagroup.org and myt5s.app endpoints.
